## 1. เป้าหมาย

ในแท็บ "อพยพกลุ่มเปราะบาง" เพิ่ม "โหมดอพยพ" สำหรับทีมช่วยเหลือ (ผู้ใหญ่บ้าน อปพร. รพ.สต.) ที่ล็อกอินแล้ว ใช้บนมือถือเป็นหลัก ทำ 4 อย่าง:

1. เห็นว่ามีบ้านต้องอพยพกี่บ้าน แยกตามระดับ แล้วกด "เริ่มอพยพตามลำดับ"
2. เห็นคิวว่าใครก่อน พร้อมเลขเดียวกันบนแผนที่
3. แตะบ้านแล้วเห็นที่หมาย มีปุ่ม นำทาง / อพยพแล้ว
4. เห็นความคืบหน้าและจำนวนที่ถึงแต่ละที่หมาย

นอกขอบเขต (ห้ามทำในงานนี้):

- ไม่ใช้ระดับน้ำหรือแบบจำลองน้ำใด ๆ ผู้ใช้สั่งชัดว่าไม่เกี่ยว ไม่ใช้ `rankEvacuationPriority` / โหมด Active ใน `app/utils/evacuation-priority.ts`
- ไม่เก็บชื่อหรือเบอร์โทรของครัวเรือน (ยังไม่มีข้อมูลและยังไม่มีความยินยอม) ปุ่มโทรให้ซ่อนไว้จนกว่าจะมีข้อมูล
- ทำเฉพาะบ้านท่าตอน อีก 3 ชุมชนยังไม่มีข้อมูล
- ไม่ทำแจ้งเตือน push / SMS

## 2. ข้อมูลที่ใช้

### 2.1 ครัวเรือน

แหล่งเดียว: ชั้น `layer-1` ชื่อ "กลุ่มเปราะบางและเหตุฉุกเฉินวิกฤต" ใน `public/mymaps/thaton.json` (129 แถว)

ฟิลด์ที่ใช้ต่อแถว: `id`, `latitude`, `longitude`, `status`, `color` และใน `fields`:
`โซน` (ชื่อหย่อม), `จำนวนสมาชิกเปราะบาง_คน`, `ประวัติน้ำท่วมบ้าน`, `อุบัติเหตุรุนแรงจากน้ำ`

ระดับตาม `legend` ของชั้นนี้ (ตรวจจากไฟล์แล้ว):

| ระดับ (`status` ขึ้นต้น) | ความหมาย | จำนวน | สี | เข้าคิว |
|---|---|---|---|---|
| 1 | วิกฤตสูงสุด (มีสมาชิกเปราะบาง + บ้านเคยท่วม) | 4 | `#a52714` | ใช่ |
| 2 | มีสมาชิกเปราะบาง (บ้านไม่เคยท่วม) | 8 | `#e65100` | ใช่ |
| 4 | เคยท่วมบ้าน (ไม่มีสมาชิกเปราะบาง) | 56 | `#673ab7` | ใช่ (รอผู้ใช้ยืนยัน ดูข้อ 7) |
| 5 | ปกติ | 61 | `#0f9d58` | ไม่ |

ไม่มีระดับ 3 ในข้อมูล อย่าสร้างขึ้นเอง

### 2.2 ที่หมาย

`data/public-evacuation-reference.json` มี 2 จุด: `TH-SHELTER-01` ศูนย์พักพิงตามแผน และ `TH-ASSEMBLY-01` จุดรวมพลตามแผน
ทั้งสองเป็นตำแหน่งประมาณจากภาพ PDF (`verificationStatus: approximate_not_field_verified`) ต้องแสดงข้อความนี้ใน UI
ความจุยังไม่รู้ (แผน F1 บอกศาลาประชาคม 100 คน วัดท่าตอน 300 คน แต่ไม่รู้ว่าตรงกับจุดไหน) ให้แสดง "ความจุรอยืนยัน"

### 2.3 กติกาเรียงคิว (ทำเป็นฟังก์ชันบริสุทธิ์ มีเทสต์)

1. ตัดระดับ 5 ออก
2. เรียงระดับน้อยไปมาก (1 → 2 → 4)
3. ระดับเท่ากัน: `จำนวนสมาชิกเปราะบาง_คน` มากกว่าก่อน
4. ยังเท่ากัน: เคยประสบเหตุรุนแรง (`อุบัติเหตุรุนแรงจากน้ำ !== 'ไม่มี'`) ก่อน
5. ยังเท่ากัน: บ้านที่ไกลจากที่หมายใกล้สุดมากกว่าไปก่อน (ระยะเส้นตรง haversine)
6. ยังเท่ากัน: เรียงตาม `id` เพื่อให้ผลคงที่
7. ที่หมายของแต่ละบ้าน = จุดที่ใกล้สุดใน 2.2

ผลที่ต้องได้กับข้อมูลปัจจุบัน (ใช้เป็นเทสต์): คิว 68 บ้าน อันดับ 1 อยู่ระดับ 1 มีสมาชิกเปราะบาง 2 คน หย่อมสายกองกาด ไปศูนย์พักพิงตามแผนราว 644 ม. ระยะไกลสุดในคิวราว 0.7 กม.

ทีมต้องลากสลับลำดับเองได้ ลำดับที่ลากแล้วต้องบันทึกลงฐานข้อมูลและชนะลำดับอัตโนมัติ

## 3. ขั้นที่ต้องทำก่อน: ปิดข้อมูลรายบ้านจากสาธารณะ

ตอนนี้ `public/mymaps/thaton.json` และ `public/evacuation/thaton.json` เปิดให้ดาวน์โหลดได้โดยไม่ล็อกอิน (ตรวจบน production แล้ว ตอบ 200) มีพิกัดรายบ้านกับข้อมูลสุขภาพ/กลุ่มเปราะบาง โหมดอพยพจะใช้ข้อมูลนี้ จึงต้องย้ายไปหลังล็อกอินก่อน

- ย้ายไฟล์ออกจาก `public/` ไปไว้ฝั่งเซิร์ฟเวอร์ (เช่น `data/private/`) และให้ API ที่ตรวจ `verifyAdminAuth` เป็นทางเดียวที่อ่านได้
- ไฟล์ที่ fetch อยู่ตอนนี้และต้องแก้: `app/utils/mymaps-review.ts` (ใช้กับปุ่ม "ข้อมูลชุมชน" มุมซ้ายบน) และ `app/utils/public-evacuation.ts` (หมุดบ้านในแท็บอพยพ)
- เทสต์ที่อ่านไฟล์ตรง: `src/lib/public-mymaps.test.ts`, `src/lib/public-evacuation.test.ts`
- **ต้องถามผู้ใช้ก่อนทำข้อนี้** ว่าปุ่ม "ข้อมูลชุมชน" มุมซ้ายบนสำหรับคนทั่วไปจะเหลืออะไร (แนะนำ: ยอดรวมรายหย่อม ไม่มีหมุดรายบ้าน) เพราะการย้ายไฟล์จะทำให้ปุ่มนั้นไม่มีข้อมูลสำหรับคนที่ไม่ได้ล็อกอิน

แผน Hobby รับได้ไม่เกิน 12 Serverless Functions และไฟล์ทุกตัวใน `api/` ที่ไม่ขึ้นต้นด้วย `_` และไม่ใช่ `.test.js` นับเป็น 1 ฟังก์ชัน (เคย deploy ล้มเพราะเรื่องนี้ ดู `memory.md` หัวข้อ 2026-10-23)
ตอนนี้มี 12 ไฟล์ (`api/express-app.js` ไม่มี default export และยังไม่ยืนยันว่า Vercel นับหรือไม่ ถือว่าเต็มเพดานแล้ว):

```

api/earth-engine/status.js  api/express-app.js  api/news/index.js
api/surveys/complete.js  api/surveys/photo.js  api/surveys/prepare.js  api/surveys/upload.js  api/surveys/waypoints.js
```

ห้ามเพิ่มไฟล์ฟังก์ชันใหม่ ให้ทำแบบเดียวกับข่าว:

- เขียนตรรกะใน `api/evacuation/_evacuation.js` (ขึ้นต้น `_` จึงไม่นับเป็นฟังก์ชัน) โฟลเดอร์ `api/evacuation/` มีอยู่แล้วแต่ว่าง

- ลงทะเบียน route เดียวกันใน `api/express-app.js` สำหรับ dev
- ตรวจว่าไฟล์ข้อมูลใน `data/private/` ถูกรวมเข้า bundle ของฟังก์ชันบน Vercel (import JSON ตรง หรือ `includeFiles`) แล้วทดสอบบน preview ก่อน

## 5. ฐานข้อมูลและ API

MongoDB ใช้ `getDb` จาก `api/surveys/_db.js` เพิ่ม index ในจุดเดียวกับ collection อื่น

```
kok_evacuation_runs   { run_id, community_id: 'thaton', status: 'open'|'closed',
                        started_at, started_by, closed_at, closed_by }
kok_evacuation_cases  { run_id, household_id, manual_rank|null,
                        status: 'waiting'|'en_route'|'arrived', destination_id,
                        updated_at, updated_by }
index: runs { community_id, status }, cases { run_id, household_id } unique
```

เก็บแค่ `household_id` (= `id` ในชั้นข้อมูล) ไม่คัดลอกพิกัดหรือฟิลด์สุขภาพลงฐานข้อมูล

ทุก endpoint ผ่าน `adminEndpoint` / `verifyAdminAuth` ใน `api/admin/_admin_shared.js` (ระยะแรกใช้รหัสผ่านแอดมินเดิม บทบาท "ทีมช่วยเหลือ" แยกเป็นงานถัดไปเมื่อผู้ใช้ตัดสิน) `updated_by` ใช้ `reviewerName` แบบเดียวกับการตรวจตัวอย่าง

| เมธอด | เส้นทาง (ผ่าน rewrite) | ทำอะไร |
|---|---|---|
| GET | `/api/admin/evacuation` | รอบที่เปิดอยู่ + คิวเรียงแล้ว + ที่หมาย + ยอดตามระดับ (ถ้าไม่มีรอบ คืนแค่ยอดและคิวตัวอย่าง) |
| POST | `/api/admin/evacuation/start` | เปิดรอบใหม่ (ถ้ามีรอบเปิดอยู่ ตอบ 409) |
| PATCH | `/api/admin/evacuation/cases/:householdId` | เปลี่ยนสถานะ waiting / en_route / arrived |
| PUT | `/api/admin/evacuation/order` | บันทึกลำดับที่ลากเอง (รับ array ของ household_id) |
| POST | `/api/admin/evacuation/close` | ปิดรอบ |

ตรวจ input ทุกตัว (status อยู่ในชุดที่กำหนด, household_id มีอยู่จริงในชั้นข้อมูล) ตอบข้อความภาษาไทยแบบเดียวกับ endpoint เดิม

## 6. หน้าจอ

ทำตามภาพต้นแบบ ใช้ token และคลาส `wv-*` เดิม อ่าน `DESIGN.md` และ `PRODUCT.md` ก่อน

- จุดเข้า: ปุ่ม "โหมดอพยพ (ทีม)" ในแท็บอพยพ ถ้ายังไม่ล็อกอิน ใช้ `KokAdminLogin.vue` เดิม
- คอมโพเนนต์ใหม่ `app/components/KokEvacuationMode.vue` (แถบบนสีเข้ม "โหมดอพยพ · บ้านท่าตอน" + ปุ่มปิด + bottom sheet) มี 4 มุมมอง:
  1. เริ่ม: 4 ช่องตามระดับ (ระดับ 5 แสดงจำนวนแต่บอกว่าไม่เข้าคิว) + ปุ่มแดง "เริ่มอพยพตามลำดับ" + ข้อความเกณฑ์เรียง
  2. คิว: แถบความคืบหน้า "อพยพแล้ว x/68" + แถว [เลขอันดับสีตามระดับ] ระดับ · เปราะบาง n คน / หย่อม · ที่หมาย ระยะ ม. / ชิปสถานะ + กดค้างลากสลับ
  3. เคส: หย่อม สมาชิกเปราะบาง ประวัติน้ำท่วม ที่หมายและระยะ + กล่องเหลือง "ผู้ติดต่อ ยังไม่มีข้อมูล" + ปุ่ม นำทาง (เปิด `https://www.google.com/maps/dir/?api=1&destination=<lat>,<lng>`) และปุ่มเขียว "อพยพแล้ว ✓"
  4. ที่หมาย: การ์ดต่อที่หมาย จำนวนที่ถึงแล้ว "ความจุรอยืนยัน" ข้อความตำแหน่งประมาณ และการ์ดแดง "ยังไม่มีพิกัด: ศาลาประชาคม วัดท่าตอน รพ.สต."
- จอกว้าง ≥ 1024px: คิวเป็นแผงซ้าย ที่หมายเป็นแผงขวา แผนที่ตรงกลาง (ภาพ `d1-command.jpg`)
- แผนที่ใน `KokMapPanel.vue`: เมื่อโหมดเปิด แสดงหมุดเลขอันดับ (สีตามระดับ, ถึงแล้วเป็นเขียว ✓) ราว 15 อันดับแรก และหมุดที่หมาย; เคสที่เลือกขยายหมุดและลากเส้นประไปที่หมาย พร้อมระบุว่าเป็นเส้นตรง ไม่ใช่เส้นทางจริง
- ระหว่างโหมดเปิด ซ่อนแถบแท็บล่างและหัวเว็บแบบในต้นแบบ
- หลายคนใช้พร้อมกัน: ดึงข้อมูลใหม่ทุก 15 วินาทีขณะโหมดเปิด (ไม่ใช้ websocket บน Vercel)
- รองรับ 360px, ปุ่มสูงอย่างน้อย 44px, ลากสลับต้องมีทางเลือกปุ่มขึ้น/ลงสำหรับผู้ใช้ที่ลากไม่ได้

## 7. ต้องถามผู้ใช้ก่อนทำส่วนนั้น

1. บ้านระดับ 4 "เคยท่วม" 56 บ้าน อยู่ในคิวอพยพ หรือแค่กลุ่มเฝ้าระวัง (ต้นแบบใส่ในคิว)
2. ปุ่ม "ข้อมูลชุมชน" สาธารณะจะเหลืออะไรหลังย้ายไฟล์ (ข้อ 3)
3. ใครล็อกอินโหมดนี้ได้ ระยะแรกใช้รหัสแอดมินเดิมพอไหม
4. มีที่หมายหรือความจุจริงเพิ่มหรือยัง

ถ้ายังไม่ได้คำตอบ ทำตามค่าที่ต้นแบบใช้ และเขียนไว้ในรายงานว่าเป็นค่าชั่วคราว

# คู่มือแอดมิน: แก้ข้อมูลแผนที่ (หย่อมบ้าน · ข้อมูลชุมชน · กลุ่มอพยพ · สถานที่สำคัญ)

เขียนเมื่อ 2026-11-03 อ้างอิงโค้ดและการทดสอบจริงของงานนี้ (ไฟล์ที่เกี่ยวข้องอยู่ท้ายเอกสาร)

## 1. หลักคิด: หน้าบ้านเห็นอย่างไร หลังบ้านเห็นอย่างนั้น

ก่อนหน้านี้ข้อมูลทั้ง 4 ชุดเป็นไฟล์ในโค้ด (`public/mymaps/thaton.json`, `data/public-evacuation-reference.json`, `public/evacuation/thaton.json`, `community-profiles.ts`) แก้ได้ต้องให้โปรแกรมเมอร์แก้ไฟล์แล้ว deploy ตอนนี้ย้ายมาอยู่ในฐานข้อมูลและแก้ผ่านหน้าแอดมิน โดยรับประกันความตรงกันด้วย 4 กลไก:

| กลไก | ทำอย่างไร |
|---|---|
| กติกาชุดเดียว | `src/lib/map-data.js` ไฟล์เดียวเป็นทั้งตัวตรวจข้อมูลและตัวสร้างข้อมูลที่หน้าบ้านเห็น ทั้ง API และหน้าแอดมินเรียกไฟล์นี้ ไม่มีกติกาซ้ำ 2 ที่ |
| ระดับและสีคำนวณเอง | แอดมินแก้ “คำตอบ” ของครัวเรือน ระบบคำนวณระดับ สี ป๊อปอัปของทั้ง 6 หัวข้อใหม่ทันที (ไม่ต้องตั้งระดับเอง จึงไม่มีทางที่คำตอบกับสีไม่ตรงกัน) |
| พรีวิว = API สาธารณะ | `GET /api/admin/map-data/preview/<หน้า>` ส่งข้อมูลชุดเดียวกับที่ `GET /api/map-data/<หน้า>` ส่งให้หน้าบ้าน ทดสอบแล้วว่าเท่ากันทุกหน้า |
| หมุดและแผนที่เดียวกัน | แผนที่แอดมินใช้ไอคอนหมุด (`app/utils/map-pin.ts`) และแผนที่ฐาน OpenStreetMap เดียวกับหน้าบ้าน และมีสวิตช์ “ดูตามหน้าบ้านจริง” |

ผลพิสูจน์ที่ตรวจแล้ว: ข้อมูลที่ API ส่งให้หน้าบ้านหลังตั้งต้นจากไฟล์เดิม มีส่วน records (ระดับ สี ป๊อปอัป ทั้ง 774 แถว) และ legend (คำอธิบายสี) เหมือนไฟล์เดิมทุกตัวอักษรเมื่อเทียบเป็นข้อความ JSON (เพิ่มเพียงช่อง `rowCount` และ `pointsPublic`) ตรวจทั้งในเทสต์และกับ MongoDB จริงบนเครื่อง

## 2. แผนผัง: หน้าบ้าน ↔ หน้าแอดมิน

| หน้าบ้าน (แท็บในแผนที่) | หน้าแอดมิน (แท็บ “ข้อมูลแผนที่”) | ข้อมูลที่แก้ได้ |
|---|---|---|
| หย่อมบ้าน (การ์ดรู้จักชุมชน) | หย่อมบ้าน | ข้อความการ์ด 4 ชุมชน, ทะเบียนหย่อม (ชื่อ ชื่อเรียกอื่น จุดกลาง การแสดง), รวมหย่อม, ผูกครัวเรือนกับหย่อม |
| ปุ่ม “ข้อมูลชุมชน” มุมซ้ายบน | ข้อมูลชุมชน | ครัวเรือน 129 หลัง × 6 หัวข้อ: พิกัด คำตอบ หย่อม การแสดง; ตั้งค่าหน้าบ้าน (ซ่อนหัวข้อ, ซ่อนหมุดรายบ้าน) |
| อพยพกลุ่มเปราะบาง | กลุ่มอพยพ | ดูกลุ่มตามระดับ, แก้เส้นทางอพยพ, ดูที่หมาย (ที่หมายแก้ที่หน้าสถานที่สำคัญ) |
| สถานที่สำคัญ | สถานที่สำคัญ | เพิ่ม/แก้/ซ่อน/ลบสถานที่ พิกัด ความจุ สถานะ |

## 3. เริ่มใช้งาน

1. เปิดเว็บ แล้วกดปุ่ม “ระบบแอดมิน” มุมขวาบน ใส่รหัสผ่านแอดมินเดิม (เครื่องพัฒนาข้ามการล็อกอินอัตโนมัติ)
2. กรอกชื่อผู้ตรวจในหน้าล็อกอิน ชื่อนี้ถูกบันทึกกับทุกการแก้ไข (ดูได้ที่ “ประวัติการแก้ไขล่าสุด” ในหน้าภาพรวม)
3. เลือกแท็บ “ข้อมูลแผนที่” จะเห็น 5 หน้าย่อย: ภาพรวม · หย่อมบ้าน · ข้อมูลชุมชน · กลุ่มอพยพ · สถานที่สำคัญ
4. ครั้งแรกที่เปิด ระบบนำข้อมูลจากไฟล์เดิมเข้าฐานข้อมูลให้เอง **ครั้งเดียว** (ไม่นำเข้าซ้ำ ไม่ทับสิ่งที่แก้ และไม่นำของที่ลบกลับมา)

สวิตช์ “ดูตามหน้าบ้านจริง” (หน้าข้อมูลชุมชน กลุ่มอพยพ สถานที่สำคัญ): ปิด = เห็นทั้งหมดรวมฉบับร่างและที่ซ่อนอยู่ (จางกว่าปกติ) เปิด = เห็นเฉพาะที่หน้าบ้านเห็นจริง ตามตั้งค่าหน้าบ้าน

## 4. แต่ละหน้าทำอะไรได้

### 4.1 ภาพรวม
- ตัวเลขสรุป: ครัวเรือนที่แสดง, หย่อม, สถานที่ที่เผยแพร่ (และรอผูกจุด), จำนวนในคิวอพยพ
- “หน้าบ้านเห็นอะไรอยู่ตอนนี้” 4 บรรทัด อ่านจากข้อมูลสาธารณะจริง พร้อมปุ่มไปจัดการแต่ละหน้า
- แจ้งเตือนเมื่อหน้าบ้านกำลังแสดงหมุดตำแหน่งรายครัวเรือน (ดูข้อ 6)
- ประวัติการแก้ไขล่าสุด 15 รายการ: ใคร ทำอะไร กับอะไร เมื่อไหร่ เปลี่ยนช่องไหน

### 4.2 หย่อมบ้าน
**การ์ดรู้จักชุมชน** (ซ้าย)
1. เลือกชุมชน แก้ข้อความ 5 ช่อง (ชื่อที่แสดง ลุ่มน้ำ ผู้คน อาชีพ ความเสี่ยง) ช่องละไม่เกิน 300 ตัวอักษร ดูตัวอย่างการ์ดที่ชาวบ้านจะเห็นด้านล่างทันที
2. กด “บันทึก” หน้าบ้านเห็นข้อความใหม่ (ไม่แก้ก็ใช้ข้อความเดิมจากชีต Village) กด “คืนข้อความเดิม” เพื่อยกเลิกที่แก้

**ทะเบียนหย่อมบ้าน** (ขวา)
- เพิ่ม/แก้ชื่อ ชื่อเรียกอื่น จุดกลางหย่อม หมายเหตุ และเลือกแสดง/ซ่อน; ลบได้เมื่อไม่มีครัวเรือนอยู่ในหย่อม (ถ้ามีระบบบอกจำนวนและให้ย้ายหรือรวมก่อน)
- **รวมหย่อม**: ระบบเตือนชื่อคล้ายกัน (เช่น “บ้านไต” กับ “หย่อมบ้านไต” ในข้อมูลจริง) กดรวม เลือกชื่อที่ใช้ต่อ ครัวเรือนย้ายตาม ชื่อเดิมเก็บเป็นชื่อเรียกอื่น
- **ผูกหย่อม**: ครัวเรือนที่ช่องหย่อมว่างในแบบสำรวจ (ตอนนี้ 3 หลัง) เลือกหลายหลังแล้วผูกกับหย่อมในครั้งเดียว
- ป้าย “หน้าบ้านซ่อนตัวเลข” = หย่อมที่มีน้อยกว่า 5 ครัวเรือน หน้าบ้านจะแสดง “น้อยกว่า 5 ครัวเรือน” แทนตัวเลข เพื่อไม่ให้ระบุตัวบ้านได้

### 4.3 ข้อมูลชุมชน
- แถบ 6 หัวข้อ (กลุ่มเปราะบาง · น้ำท่วม · พึ่งพิงแม่น้ำ · ภัยแล้ง · สุขภาพ · เตรียมพร้อม) เลือกแล้วแผนที่และคำอธิบายสีเปลี่ยนตาม พร้อมยอดแต่ละระดับ (กดแถวเพื่อกรอง)
- ตารางครัวเรือน กรองตามหย่อม / การแสดง ค้นด้วยรหัส เช่น MM1-012
- **แก้ครัวเรือน**: คลิกหมุด หรือรหัสในตาราง แล้วแก้ในแผงขวา
  - พิกัด (พิมพ์ หรือกด “เลือกตำแหน่งจากแผนที่”), หย่อม, ติ๊กแสดงบนหน้าบ้าน
  - คำตอบทุกข้อเป็นตัวเลือกตามแบบสำรวจจริง (ไม่พิมพ์เอง) แยกเป็น 6 กลุ่ม แต่ละกลุ่มบอก “ระดับ n” สดทันทีที่เปลี่ยนคำตอบ
  - เห็น “ป๊อปอัปที่หน้าบ้านเห็น” ก่อนบันทึก
  - กดบันทึก ระบบบอกว่าระดับหัวข้อไหนเปลี่ยนจากอะไรเป็นอะไร
- **เพิ่มครัวเรือน**: รหัสใหม่ต่อจากเลขสูงสุด (MM1-130 …) ต้องมีพิกัดและตอบข้อที่มีดาว (*) ให้ครบ
- ปุ่มตา = ซ่อน/แสดงบนหน้าบ้าน (ข้อมูลยังอยู่) ปุ่มถังขยะ = ลบถาวร ลบไม่ได้ถ้าครัวเรือนอยู่ในรอบอพยพที่เปิดอยู่
- **ตั้งค่าหน้าบ้าน**: ติ๊กหัวข้อที่จะแสดง (ซ่อนเรื่องสุขภาพได้) และสวิตช์ “แสดงหมุดตำแหน่งรายครัวเรือนต่อสาธารณะ” ปิดแล้วหน้าบ้านเห็นเฉพาะยอดรวมแต่ละระดับ

### 4.4 กลุ่มอพยพ
- การ์ด 4 ระดับ: ระดับ 1, 2, 4 เข้าคิวอพยพ ระดับ 5 (ปกติ) ไม่เข้า (ตอนนี้ 4 / 8 / 56 / 61 = ในคิว 68 หลัง)
- แผนที่: หมุดครัวเรือนในคิว + ที่หมาย + เส้นทาง กดหมุดครัวเรือนไปแก้ที่หน้าข้อมูลชุมชน กดที่หมายไปแก้ที่หน้าสถานที่สำคัญ
- **เส้นทางอพยพ**: แก้เส้น (คลิกแผนที่ต่อจุด ลากจุดเพื่อย้าย จุดแรกสีเขียว จุดสุดท้ายสีแดง) ลบจุดสุดท้าย เพิ่มเส้นใหม่ ลบเส้น บันทึกแล้วหน้าบ้านเห็นเส้นใหม่ จำกัด 400 จุดรวม
- ไม่ต้อง “จัดกลุ่มอพยพ” ด้วยมือ: กลุ่มคำนวณจากคำตอบของครัวเรือน (มีสมาชิกเปราะบาง + เคยท่วม ฯลฯ)

### 4.5 สถานที่สำคัญ
- ชนิดที่เลือกได้ (มาจากข้อ R16/R24): ศูนย์พักพิง · จุดรวมพล · จุดย้ายรถ · รพ.สต./โรงพยาบาล · วัด · โรงเรียน · ศาลาประชาคม · อบต./เทศบาล · ประปาชุมชน · ท่าเรือ · ครัวกลาง · จุดประสานงาน · อื่น ๆ
- **เพิ่ม/แก้**: ชื่อ ชนิด ชุมชน ที่มาของข้อมูล พิกัด (หรือเลือกจากแผนที่) ความแม่นยำ (ประมาณ/ยืนยันภาคสนาม) ความพร้อมใช้งาน ความจุตามแผน ความจุที่ตรวจแล้ว วันที่ตรวจ หมายเหตุ สถานะ (ฉบับร่าง/เผยแพร่)
- **ไม่มีพิกัดได้** (ข้อ R24): สถานที่นั้นขึ้นหน้าบ้านเป็นรายการ “รอผูกจุด” ไม่ปักหมุดเดาตำแหน่ง เมื่อได้พิกัดแล้วค่อยกรอก
- ความจุตามแผนหน้าบ้านแสดงว่า “ตามแผน (ยังไม่ยืนยันความพร้อมวันนี้)” ไม่ใช่การบอกว่ารับคนได้ (ข้อ R16)
- ไม่มีช่องเบอร์โทร/ผู้ติดต่อ (ข้อ R24, ข้อ R16) ส่งมาก็ไม่เก็บ
- ปุ่มตา = ซ่อน/เผยแพร่ ลบไม่ได้ถ้าเป็นที่หมายของรอบอพยพที่เปิดอยู่
- แท็บ “สถานที่สำคัญ” บนหน้าบ้านเปิดเองเมื่อชุมชนนั้นมีสถานที่ที่เผยแพร่อย่างน้อย 1 แห่ง ไม่มีก็ปิดเหมือนเดิม
- ศูนย์พักพิงและจุดรวมพลที่เผยแพร่ในชุมชนท่าตอน คือที่หมายที่หน้าแท็บอพยพวาดบนแผนที่

## 5. กติการะดับ (คำนวณอัตโนมัติ ตรวจกับข้อมูลจริงครบทุกแถว)

| หัวข้อ | ระดับ (ตามลำดับความรุนแรง) | ตัดสินจาก |
|---|---|---|
| 1 กลุ่มเปราะบาง | 1 มีสมาชิกเปราะบาง + เคยท่วม · 2 มีสมาชิกเปราะบางแต่ไม่เคยท่วม · 4 เคยท่วมไม่มีสมาชิกเปราะบาง · 5 ปกติ (ไม่มีระดับ 3) | จำนวนสมาชิกเปราะบาง, ประวัติน้ำท่วมบ้าน |
| 2 น้ำท่วม | 1 มิดหัว · 2 เอว–อก · 3 เข่า–เอว · 4 ต่ำกว่าเข่า · 5 ไม่ท่วม | ระดับความลึกน้ำท่วมที่บ้าน |
| 3 พึ่งพิงแม่น้ำ | 1 ใช้น้ำกกตรงเป็นประจำ · 2 ใช้ทำเกษตร · 3 ไม่ใช้แต่ไม่ปลอดภัย · 4 รู้สึกปลอดภัย/ปานกลาง | การใช้น้ำ ความรู้สึกปลอดภัย |
| 4 ภัยแล้ง | 1 ไม่มีน้ำสำรอง+รับมือ ≤3 วัน · 2 ไม่มีภาชนะ · 3 รับมือ ≤3 วัน · 4 มีระบบสำรอง/นานกว่า 3 วัน | ระบบน้ำสำรอง ระยะเวลารับมือ |
| 5 สุขภาพ | 1 อาการรุนแรง/วิกฤต · 2 กังวลมากที่สุด+ตรวจน้อย · 3 กังวลมากที่สุด · 4 เข้าถึงการตรวจน้อย/ไม่ได้ · 5 ปกติ | อาการป่วย การเข้าถึงตรวจคัดกรอง ความกังวล |
| 6 เตรียมพร้อม | 1 ไม่เคยได้เตือน+ไม่มีแผน · 2 ไม่มีแผน · 3 ไม่ค่อยเชื่อมั่นความโปร่งใส · 4 มีความพร้อม/เชื่อมั่น | เตือนภัย แผนรับมือ ความเชื่อมั่น |

สีและป้ายของแต่ละระดับคัดจากคำอธิบายสีของไฟล์ My Maps เดิม (`src/lib/map-data-options.js`)

## 6. ความเป็นส่วนตัวและสิทธิ์

- ทุกหน้าแอดมินและทุกคำสั่งแก้ข้อมูลต้องมี token แอดมิน (รหัสผ่านเดิม) ไม่มี token ได้ 401; ข้อมูลสาธารณะอ่านได้โดยไม่ล็อกอินแต่เป็นข้อมูลที่ผ่านกติกาหน้าบ้านแล้วเท่านั้น
- ค่าเริ่มต้น “แสดงหมุดตำแหน่งรายครัวเรือนต่อสาธารณะ” **เปิดอยู่** เพื่อให้หน้าบ้านเหมือนเดิมทุกอย่าง (ตามที่บันทึกใน `memory.md` 2026-11-03) แต่ `DESIGN.md` และข้อ R15 ให้หน้าสาธารณะแสดงเฉพาะยอดรวม จึงมีสวิตช์ให้ปิดในหน้า “ข้อมูลชุมชน” → “ตั้งค่าหน้าบ้าน” โดยไม่ต้องแก้โค้ด เจ้าของโครงการเป็นผู้ตัดสินใจ
- ไฟล์ `public/mymaps/thaton.json` และ `public/evacuation/thaton.json` ยังดาวน์โหลดได้โดยตรง (ไม่ได้ย้ายในงานนี้) การปิดสวิตช์หมุดจึงยังไม่ปิดไฟล์เหล่านี้ ต้องย้ายตามแผนในเอกสารส่งต่อคิวอพยพข้อ 3 ด้วย
- ไม่เก็บชื่อ เบอร์โทร หรือที่อยู่ของครัวเรือนและสถานที่

## 7. ฟังก์ชันอ้างอิง

### 7.1 ฝั่งหน้าแอดมิน (`app/utils/map-data-admin.ts`): `createMapDataClient(onSessionExpired?)`
ทุกฟังก์ชันคืน Promise ถ้าไม่สำเร็จ throw `MapDataError` (มี `.status` `.errors` ข้อความไทย)

| กลุ่ม | ฟังก์ชัน |
|---|---|
| ทั่วไป | `summary()` · `audit(limit)` · `preview(target, community?)` target = community, places, hamlets, routes, profiles, availability |
| ตั้งค่า | `settings.get()` · `settings.save({ hiddenLayers, pointsPublic, surveyDate })` |
| สถานที่ | `places.list(filters)` · `places.save(place)` (ไม่มี id = เพิ่ม) · `places.publish(id, published)` · `places.remove(id)` |
| หย่อม | `hamlets.list()` · `hamlets.save(h)` · `hamlets.remove(id)` · `hamlets.merge(fromIds, intoId)` |
| ครัวเรือน | `households.list(filters)` · `households.get(id)` · `households.save(id\|null, value)` · `households.publish(id, published)` · `households.assign(ids, hamletId)` · `households.remove(id)` |
| อพยพ | `evacuation.overview()` · `evacuation.saveRoute(routes, alignment, source)` |
| การ์ดชุมชน | `profiles.list()` · `profiles.save(communityId, profile)` · `profiles.reset(communityId)` |

สถานะรวม (กำลังทำงาน ข้อความสำเร็จ/ผิดพลาด โหมดดูตามหน้าบ้าน) อยู่ใน `useAdminMapData()` (`app/composables/useAdminMapData.ts`)

### 7.2 กติกากลาง (`src/lib/map-data.js`, ชนิดข้อมูลใน `map-data.d.ts`)
`classifyLayer` · `classifyHousehold` · `buildCommunityReview` (สร้างข้อมูลที่หน้าบ้านเห็น) · `levelGroups` · `seedFromReview` · `validateHousehold` · `validateHamlet` · `validatePlace` · `validateRoutes` · `validateProfile` · `suggestHamletMerges` · `hamletCounts` · `publicHamletSummary` (ซ่อนจำนวนน้อยกว่า 5) · `publicPlaces` / `toPublicPlace` · `evacuationDestinations` · `householdFields` · `PLACE_KINDS`

### 7.3 ฝั่งเซิร์ฟเวอร์ (`api/mapdata/_mapdata_db.js`)
ฟังก์ชันอ่าน/เขียนฐานข้อมูล เช่น `listHouseholds` `updateHousehold` `mergeHamlets` `createPlace` `saveRoutes` `publicCommunityPayload` ฯลฯ และ **`listEvacuationDestinations(settings)`** ให้โหมดอพยพอ่านที่หมายจากทะเบียนสถานที่แทนไฟล์ (ดูข้อ 9)

### 7.4 เส้นทาง API
แอดมิน (ต้องมี token) ทั้งหมดขึ้นต้น `/api/admin/map-data`

| เมธอด | เส้นทาง | ทำอะไร |
|---|---|---|
| GET | `` · `/audit` · `/preview/<หน้า>` | สรุป · ประวัติ · พรีวิว |
| GET/PUT | `/settings` | ตั้งค่าหน้าบ้าน |
| GET/POST | `/places` | รายการ · เพิ่ม |
| GET/PUT/DELETE | `/places/<id>` | ดู · แก้ · ลบ |
| POST | `/places/<id>/publish` | เผยแพร่/ซ่อน `{published}` |
| GET/POST | `/hamlets` | รายการ (พร้อมคำแนะนำรวมหย่อม) · เพิ่ม |
| PUT/DELETE | `/hamlets/<id>` | แก้ · ลบ |
| POST | `/hamlets/merge` | รวมหย่อม `{from_ids, into_id}` |
| GET/POST | `/households` | รายการ (กรอง/แบ่งหน้า) · เพิ่ม |
| GET/PUT/DELETE | `/households/<id>` | ดู (พร้อมพรีวิว) · แก้ · ลบ |
| POST | `/households/<id>/publish` · `/households/assign` | ซ่อน/แสดง · ผูกหย่อมหลายหลัง |
| GET | `/evacuation` | กลุ่ม เส้นทาง ที่หมาย |
| PUT | `/evacuation/route` | บันทึกเส้นทาง |
| GET/PUT/DELETE | `/profiles` · `/profiles/<ชุมชน>` | การ์ดชุมชน |

สาธารณะ (ไม่ต้องล็อกอิน): `GET /api/map-data/<community|places|hamlets|routes|profiles|availability>` (`?community=thaton`)

รหัสตอบกลับ: 400 ข้อมูลผิด (ข้อความไทย + `errors`), 401 ยังไม่ล็อกอิน, 404 ไม่พบ, 405 เมธอดไม่รองรับ, 409 ลบไม่ได้เพราะยังถูกใช้งาน, 503 ระบบไม่พร้อม

## 8. ข้อมูลในฐานข้อมูล (MongoDB)

`kok_map_households` (1 เอกสารต่อบ้าน รวมคำตอบทั้ง 6 หัวข้อ; รหัส = รหัสแถวหัวข้อ 1 เช่น MM1-001 เพื่อให้คิวอพยพเดิมใช้ต่อได้) · `kok_map_hamlets` · `kok_map_places` (รหัสเดิม TH-SHELTER-01 / TH-ASSEMBLY-01 คงไว้) · `kok_map_settings` (ตั้งค่าหน้าบ้าน เส้นทาง ตัวบอกว่านำเข้าครั้งแรกแล้ว) · `kok_map_profiles` (ข้อความการ์ดที่แก้) · `kok_map_audit` (ประวัติ: ใคร ทำอะไร เมื่อไหร่ เปลี่ยนช่องไหน)

## 9. การเชื่อมกับโหมดอพยพ (งานคนละส่วน ยังไม่ได้แก้ให้)

`api/evacuation/_evacuation.js` (ของงานคิวอพยพ) ยังอ่านครัวเรือนและที่หมายจากไฟล์ ผมไม่ได้แก้ไฟล์นั้นเพื่อไม่ชนงานที่ยังไม่ commit ของอีกคน เมื่อพร้อมให้เปลี่ยนทีละจุด: ที่หมาย → `listEvacuationDestinations(settings)`; ครัวเรือน → `allHouseholds(settings)` แล้วใช้ `buildCommunityReview` หรือคำตอบ + `classifyHousehold` ได้ผลระดับเดียวกับหน้าบ้าน รหัสครัวเรือนและที่หมายเดิมยังใช้ได้

## 10. การ deploy และข้อควรตรวจ

- ไม่เพิ่มไฟล์ฟังก์ชันของ Vercel (แผน Hobby จำกัด 12) คำขอทั้งหมดผ่านฟังก์ชันเดิมด้วย `?route=mapdata` ใน `api/admin/review.js` (แอดมิน) และ `api/surveys/waypoints.js` (สาธารณะ) + rewrite ใน `vercel.json`; เทสต์ `api/mapdata/mapdata.test.js` ยืนยันจำนวนไฟล์ยังเป็น 12
- **ต้องตรวจบน Vercel preview ก่อนขึ้นจริง**: ไฟล์ตั้งต้น (`public/mymaps/thaton.json` ฯลฯ) ถูกอ่านด้วย `new URL(..., import.meta.url)` ซึ่งตัวรวมไฟล์ของ Vercel มักตามไปรวมให้ แต่ผมทดสอบบน Vercel ไม่ได้ ถ้าไม่ถูกรวม ฐานข้อมูลจะว่างและไม่ถูกนำเข้า API สาธารณะตอบ 503 หน้าบ้านจึงถอยไปใช้ไฟล์เดิมเอง (เทสต์ยืนยันแล้ว) แต่หน้าแอดมินจะไม่มีข้อมูล แก้ด้วย `includeFiles` ใน `vercel.json`
- แคช: CDN ของ Vercel เก็บข้อมูลสาธารณะ 20 วินาที (`Vercel-CDN-Cache-Control`) เบราว์เซอร์ถามใหม่ทุกครั้ง หลังแอดมินบันทึกหน้าบ้านจึงเห็นภายใน 20 วินาที
- ถ้า API หรือฐานข้อมูลล่ม หน้าบ้านถอยไปใช้ไฟล์เดิม (ข้อมูลชุมชน ที่หมาย เส้นทาง การ์ด) แต่แท็บ “สถานที่สำคัญ” ปิด

## 11. ข้อจำกัดและเรื่องที่ต้องตัดสินใจ

1. สวิตช์หมุดรายบ้านต่อสาธารณะ: เปิดอยู่ตามเดิม (ข้อ 6) เจ้าของโครงการเลือกเอง
2. แท็บ “สถานที่สำคัญ” บนหน้าบ้านเปิดขึ้นเองตอนนี้ เพราะมีศูนย์พักพิงและจุดรวมพล 2 แห่งที่เผยแพร่ (แห่งเดียวกับที่แท็บอพยพแสดงอยู่แล้ว ตำแหน่งประมาณ) ถ้าไม่ต้องการให้เปิด ต้องซ่อนทั้ง 2 แห่ง ซึ่งจะหายจากแท็บอพยพด้วย
3. สิทธิ์: ใช้รหัสแอดมินเดียว ยังไม่แยกบทบาท (ทีมช่วยเหลือ/ผู้ดูแล)
4. ลบเป็นถาวร ไม่มี undo (มีประวัติบอกว่าใครลบอะไร แต่ไม่เก็บเนื้อหาเดิม) ใช้ “ซ่อน” แทนเมื่อไม่แน่ใจ
5. ยังไม่มีนำเข้า/ส่งออก CSV และยังไม่ได้ตรวจหน้าแอดมินด้วยสายตาบนจอจริงแบบภาพ (ตรวจด้วย DOM และ e2e ที่ 375/768/1024/1440 px ไม่เลื่อนข้าง)
6. ชุมชนอื่นนอกท่าตอนยังไม่มีข้อมูลครัวเรือน (มีเฉพาะสถานที่และการ์ดชุมชนที่เพิ่มได้)
